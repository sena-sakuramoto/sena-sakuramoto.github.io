# 飲食店レイアウト・シミュレーター

業態・平面形状・ゾーニング・通路幅・席ミックスなどの条件から、客席+厨房レイアウトのパターンと席数を自動生成する静的Webツール。
GitHub Pages 上では `/tools/layout-sim/` で公開される。

## 構成

| ファイル | 役割 |
|---|---|
| `presets.js` | ルールテーブル(家具寸法・ベンチモジュール・業態プリセット・トイレ目安・スコア重み)。**数値調整はここだけ触ればよい** |
| `geometry.js` | 多角形ユーティリティ(包含判定・半平面クリップ・矩形クリップ・距離) |
| `engine.js` | 配置エンジン。境界多角形の構築 → 厨房スラブ(面積二分探索)→ デシャップ/カウンター/通路 → WC → ベンチ席 → テーブル充填 → 多目的評価 |
| `dxf.js` | DXF(R12)書き出し。レイヤー分けされた線分+文字。Rhinoでそのまま開ける(単位mm) |
| `threedm.js` | .3dm書き出し(rhino3dm.js/WASMをCDNから遅延ロード)。レイヤー色付きポリライン+ラベルのTextDot |
| `gh/layout_from_json.py` | GHPythonブリッジ。JSON書き出しをGrasshopper上に再構築するスクリプト |
| `app.js` | UIバインド・SVG描画・KPI表示 |
| `index.html` / `style.css` | 画面 |

## v2 の機能

- **平面形状**: 矩形 / L字(欠き位置・寸法指定)/ 自由入力(頂点座標)。柱(矩形)も任意本数
- **ゾーニング指定**: 厨房位置(最奥/左/右)、入口位置(前面 左/中央/右)、WC位置(四隅)。
  収まらない場合は近傍へ自動スライド。WCが厨房帯に食い込む場合は厨房面積から控除して警告
- **席パターン**: 2/4/6人卓(6人卓は優先卓数指定)、壁ベンチ(バンケット、4人/2人モジュール)、厨房前カウンター
- **評価**: 総席数・坪効率に加え、配膳動線(デシャップ→各卓 平均・直線)、避難距離(各卓→入口 最大・直線)、
  壁際席率、総合スコア(重み付き0〜100)。スイープ比較はスコア順

## 座標系

原点=店舗左前(入口側)、x=間口方向、y=奥行方向(入口 y=0)。単位mm。
DXF/3dmも同じ座標系で出力されるため、Rhino上では入口が下になる。

## Rhino / Grasshopper 連携

- **3DM書き出し**: rhino3dm.jsでネイティブ.3dmを生成(レイヤー色・ラベルTextDot付き)。Rhinoで直接開ける。CDNが使えないオフライン環境ではDXFを使用
- **DXF書き出し**: そのままRhinoにインポート(レイヤー: WALL / KITCHEN / DISHUP / COUNTER / TABLE / BENCH / CHAIR / AISLE / WC / ENTRANCE / COLUMN)
- **JSON書き出し → GHPython**: `gh/layout_from_json.py` をGHPythonコンポーネントに貼り、File Pathで layout.json を接続すると、Grasshopper上に矩形・多角形カーブ(rects/layers/labels)と指標(info)が展開される

## 主な前提値(presets.js)

- 2人卓 700×700 / 4人卓 1500×750 / 6人卓 1800×750、椅子スペース450
- 壁ベンチ: ベンチ500+テーブル700+椅子側450(奥行計1650)、4人モジュール幅1400 / 2人幅750
- カウンター: 天板奥行450+椅子ゾーン600、ピッチ600〜700
- デシャップ台: 奥行600(厨房客席側)
- トイレ便器数: 客席数ベースの目安(〜20席:1、〜40席:2、〜70席:3、〜100席:4、以降50席ごと+1)。
  **実際は所轄保健所・自治体条例・ビル管理基準の確認が必須**

## 既知の制約(v2)

- 配膳・避難距離は**直線距離**(経路探索なし)。法規・避難計画の検証機能はない
- 壁ベンチは軸平行の壁のみ(斜め壁はスキップ)
- 小上がり・個室モジュールは未実装
- 入口は前面(y=0側)前提
